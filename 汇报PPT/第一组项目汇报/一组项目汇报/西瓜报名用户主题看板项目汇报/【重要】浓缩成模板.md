### 解决内存溢出问题（yarn，mr，硬件，分批，分区，分桶）

```mysql
修改Yarn内存配置？
yarn.nodemanager.resource.memory-mb、yarn.scheduler.maximum-allocation-mb 要一样值。
yarn.app.mapreduce.am.command-opts 修改为略小的值。

修改MR内存配置，不能高于Yarn的内存配置
mapreduce.map.memory.mb、mapreduce.reduce.memory.mb的内存设置  （大）  
》
mapreduce.map.java.opts、mapreduce.reduce.java.opts的配置     （小）

增加内存硬件，分批处理数据

分区和分桶采样
MapJoin能够提高hive分析性能，但是占用内存较大。关闭mapjoin
set hive.auto.convert.join=false;
启用有序动态分区，reducer仅随时保持一个记录写入程序，从而降低对 reducer产生的内存压力。
set hive.optimize.sort.dynamic.partition=ture
```

### 常用插入设置

```MYSQL
--  分区
SET hive.exec.dynamic.partition=true;
SET hive.exec.dynamic.partition.mode=nonstrict;
set hive.exec.max.dynamic.partitions.pernode=10000;
set hive.exec.max.dynamic.partitions=100000;
set hive.exec.max.created.files=150000;
--  hive压缩
set hive.exec.compress.intermediate=true;
set hive.exec.compress.output=true;
--  写入时压缩生效
set hive.exec.orc.compression.strategy=COMPRESSION;
--  SMB分桶
set hive.enforce.bucketing=true;-- 写入数据,强制分桶
set hive.enforce.sorting=true;  -- 写入数据,强制排序
set hive.optimize.bucketmapjoin = true;-- 开启bucket-map-join
set hive.auto.convert.sortmerge.join=true;-- 开启SMB Join
set hive.auto.convert.sortmerge.join.noconditionaltask=true;-- 开启SMB Join
--  join数据倾斜
set hive.optimize.skewjoin=true;-- Skew-Join开启运行时倾斜优化
set hive.skewjoin.key=100000;	-- Skew-Join设定倾斜阈值，行数>=10万行 范围比较广
set hive.optimize.skewjoin.compiletime=true;-- Skew-Join开启编译时优化
set hive.optimize.union.remove=true;-- union优化，减少unionall对磁盘的操作，直接在内存中执行
--  group倾斜
set hive.groupby.skewindata=true;-- MR Job随机数打散，不能有distinct去重操作存在
```

### 其他优化小手段

#### 关联优化器

减少shuffle，提升性能。

```sql
set hive.optimize.correlation=true;
```

#### Hive-Job并行

默认情况下，一次只执行一个阶段。不过，如果某些阶段不是互相依赖，是可以并行执行的。

```sql
set hive.exec.parallel=true;
set hive.exec.parallel.thread.number=16;
```

#### 小文件合并

平均文件大小小于阈值，则触发合并，默认值：16M。

![image-20200914234200630](pic.zxedu/image-20200914234200630.png)

#### 矢量查询

批量查询数据，必须以**ORC格式**存储数据。

```sql
set hive.vectorized.execution.enabled=true;
```

#### 读取零拷贝

减少读取的数据量，必须以**ORC格式**存储数据。

```sql
set hive.exec.orc.zerocopy=true;
```

    select
            dt,
            customer_id,
            school_id,
            school_name,
            subject_id,
            subject_name,
            row_number() over(partition by customer_id) rn_school,
            row_number() over(partition by customer_id) rn_subject
    from hive.itcast_dwb.customer_dwb
    where payment_state='PAID'
        and school_id is not null
        and subject_id is not null
)

    substring (dt,1,4) as year_code,
    substring (dt,1,7) as month_code,
    substring (dt,1,10) as date_code,

    school_id,
    school_name,
    subject_id,
    subject_name,
    case
        -- 判断分组时，先判断最小粒度的分组，再判断大的分组
        when grouping(school_id)=0
        then 'school'
        when grouping(subject_id)=0
        then 'subject'
    end
    as group_type,
    case
        when grouping(school_id)=0
        then count(DISTINCT if(rn_school=1, customer_id, null))
        when grouping(subject_id)=0
        then count(DISTINCT if(rn_subject=1, customer_id, null))
    end
    as total_customer,
    dt
from base
group by
grouping sets(
    (dt,school_id,school_name),
    (dt,subject_id,subject_name)
)
